# WindAgent: сценарий живого демо

Продолжительность: **6 минут 20 секунд**. Это план выступления, а не измерение скорости системы. Сокращённый вариант и резервный маршрут приведены ниже. Язык интерфейса: RU.

## Подготовка до выступления

Из корня репозитория активировать подготовленное окружение с зависимостями из `requirements.txt`. В PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
$env:WINDAGENT_OFFLINE = "1"
$env:LLM_PROVIDER = "none"
$env:WINDAGENT_OUTPUTS_DIR = Join-Path (Get-Location) ".venv\demo-outputs"
New-Item -ItemType Directory -Force -Path $env:WINDAGENT_OUTPUTS_DIR | Out-Null
Copy-Item -LiteralPath ".\outputs\shelek" -Destination $env:WINDAGENT_OUTPUTS_DIR -Recurse -Force
python -m streamlit run app/streamlit_app.py --browser.gatherUsageStats false
```

Открыть адрес из сообщения Streamlit. В соседнем терминале активировать то же окружение и задать те же переменные:

```powershell
.\.venv\Scripts\Activate.ps1
$env:WINDAGENT_OFFLINE = "1"
$env:LLM_PROVIDER = "none"
$env:WINDAGENT_OUTPUTS_DIR = Join-Path (Get-Location) ".venv\demo-outputs"
```

Копия результатов содержит сохранённый LLM-выпуск для дашборда. Новый CLI-выпуск записывается отдельно в `adhoc/`, согласно [контракту](../CONTRACTS.md), и не заменяет архив в `runs/`. `WINDAGENT_OFFLINE` управляет доступом к погоде, а `LLM_PROVIDER=none` отдельно отключает обращение к LLM. Подготовить демо заранее, проверить наличие модели и кэша. Время исполнения команды не обещать.

После обновления ядра `cdcbe11` актуальные [метрики валидации](../../outputs/shelek/validation/metrics.json) отличаются от прежнего блока README, а сохранённые выпуски отражают предыдущий расчёт. Ниже метрики качества взяты из JSON; числа сохранённого выпуска используются только для объяснения его истории. До синхронизации артефактов не обещать численного совпадения нового CLI-прогона с архивом.

В интерфейсе выбрать `shelek`, «Время данных», «Исторические», выпуск `2026-01-31 00:00`, версию `v1`. Дата и исходная версия: [run.json](../../outputs/shelek/runs/2026-01-31_0000/run.json), поля `issue_time_data_clock`, `versions`.

## Ход выступления

Все отметки времени ниже обозначают план выступления. Числа результатов сопровождаются источниками.

### 0:00–0:40 · Задача оператора

**На экране:** вкладка «Прогноз», профиль выработки.

**Речь:** «Оператору ВЭС нужен почасовой график выработки на следующие сутки, чтобы планировать режим работы и резервы. WindAgent собирает доступные прогнозы погоды, проверяет их и публикует прогноз с диапазоном неопределённости. По журналу можно понять, как агент получил результат».

Показать средний прогноз ВЭС и переключатель «Показать турбины». «Здесь нормированная мощность от нуля до единицы и среднее двух турбин. Эти значения нельзя представлять как мегаватты или денежную экономию». Источник определения шкалы и ВЭС: [README, блок METRICS](../../README.md#2-краткое-описание).

### 0:40–1:30 · Прогноз и часы

**На экране:** граница внутрисуточного и следующего дня, диапазон квантилей, «Происхождение прогноза».

**Речь:** «Для выбранного выпуска горизонт составляет 48 часов. В сабмит входят часы с упреждением от 24 до 47: для этого выпуска это следующий день, первое февраля».

Источники: [run.json](../../outputs/shelek/runs/2026-01-31_0000/run.json), `horizon_h=48`; [submission_day_ahead.csv](../../outputs/shelek/test_period/submission_day_ahead.csv), строки с `issue_id=2026-01-31_0000`, столбцы `lead_h`, `target_time_data_clock`.

Показать переключение часов и вернуть «Время данных». «Система хранит UTC отдельно от часов исходного регистратора и официального времени. При показе меняется подпись времени, а не прогноз». Для численного объяснения часов регистратора использовать [README, блок METRICS](../../README.md#2-краткое-описание): фиксированный UTC+6. Не выдавать статистический вывод о часах за паспортную спецификацию регистратора.

### 1:30–2:15 · Действия агента и повторный выпуск

**На экране:** «Агент» → «Журнал выполнения», затем «Как изменился прогноз».

**Речь:** «В сохранённом выпуске решения принимала политика LLM. Она вызывает инструменты и пишет объяснение. Числа прогноза вычисляет модель машинного обучения. Повторный выпуск использует более свежие опубликованные прогнозы погоды».

Показать поля `policy=llm`, `provider=openai`, `model=gpt-5.4-mini` в [исходном run.json](../../outputs/shelek/runs/2026-01-31_0000/run.json). В нём версии `1` и `2`, моменты `as_of_utc` различаются на **6 часов**. Величина пересмотра в `kpis.revision_mae_v2_vs_v1` равна **0.0324**. Это отличие прогнозов между версиями, а не ошибка относительно факта.

Не привязывать карточки KPI к выбранной версии без проверки: интерфейс сообщает, что метаданные могут описывать последний опубликованный вариант.

### 2:15–3:15 · Запуск настоящего CLI

**В терминале:** выполнить именно эту команду:

```powershell
python -m windagent forecast --issue "2026-01-31 00:00" -v
```

Момент выпуска взят из [run.json](../../outputs/shelek/runs/2026-01-31_0000/run.json), `issue_time_data_clock`. Переменные окружения заданы при подготовке.

**Речь во время выполнения:** «Сейчас запускается новый прогноз из локального погодного кэша. Для воспроизводимого показа без сети выбрана политика правил. Она использует те же инструменты. Сохранённый ранее LLM-журнал остаётся отдельным подтверждением работы LLM-политики».

Показать события получения погоды, проверки, расчёта и публикации. Новый журнал должен показывать `rules/none`, а погода поступать из кэша. Открыть метаданные именно нового прогона:

```powershell
Get-Content -LiteralPath (Join-Path $env:WINDAGENT_OUTPUTS_DIR "shelek\adhoc\2026-01-31_0000\run.json")
```

Вернуться в браузер для просмотра валидации. Исторический список дашборда читает `runs/`; обновление страницы не превращает сохранённый выпуск в результат нового CLI-запуска. Не называть новый запуск LLM-демонстрацией.

Если команда ещё работает, перейти к следующей вкладке и вернуться к результату позднее. Если она завершилась с ошибкой, показать исходный [журнал](../../outputs/shelek/runs/2026-01-31_0000/trace.jsonl) и прямо назвать его сохранённым прогоном.

### 5:20–6:20 · Применение и ограничения

**На экране:** «Как это работает».

Для промышленной работы следующий шаг — поток измерений, мониторинг качества и запуск при выходе новых прогнозов погоды. Сейчас перед нами воспроизводимый прототип с проверяемыми выходными файлами».

Завершить на профиле выработки и оставить открытым файл сабмита для вопросов.

## Сокращение и резерв

- Для выступления на **5 минут** убрать подробное переключение часов и оставить один показатель качества. Это редакторский вариант тайминга.
- Если браузер недоступен, показать существующие [скриншоты интерфейса](../figures/ui/) и исходные файлы результатов. Называть их сохранёнными материалами.
- Если нет сети или LLM-ключа, использовать подготовленный офлайн-маршрут выше. «Прогноз сейчас» для этого сценария не выбирать: в историческом кэше может не быть текущей погоды.
- При повторном CLI-запуске обновляется каталог `adhoc/`. Архивные результаты в `runs/` остаются отдельно. Исходные результаты в `outputs/` не пересчитывать для показа.

## Источники чисел

Ссылки выше ведут к исходным файлам репозитория, а не к тестовым фикстурам. При обновлении результатов сверить значения перед выступлением. Порядковые номера, продолжительность выступления, адрес локального сервера и синтаксис команд являются инструкциями показа, а не заявленными результатами модели.
